# Karpathy Guidelines

## Think Before Coding

State assumptions and tradeoffs before implementation. Ask when ambiguity would materially change the result.

## Simplicity First

Use the minimum code that solves the requested problem. Avoid speculative abstractions and features.

## Surgical Changes

Touch only what the task requires, preserve the existing style, and leave unrelated code unchanged.

## Goal-Driven Execution

Define verifiable success criteria and keep iterating until the relevant tests or checks pass.
